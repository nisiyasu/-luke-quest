### 提示されたプロンプト全文

LUKE QUEST MODERN 3D VISUAL PROTOTYPE を作成してください。

目的は、現在のDOM/CSSベースの2Dタイル表現ではなく、ブラウザの限界に挑むような「圧倒的に美しくリッチなモダン3D JRPG風」の見た目を、まず1エリアの技術検証として成立させることです。

重要方針

* これは既存本線の即時全面置換ではなく、技術検証用プロトタイプです。
* 対象は 王都近郊フィールドの1画面相当エリアのみ としてください。
* HTML / CSS / JavaScript はすべて1つの .html ファイルにまとめてください。
* 描画は HTML5 Canvas + WebGL を使い、Three.js を利用してください。
* Three.js は head内でCDNから読み込み、実際に動作する形にしてください。例として cdnjs のURLを使ってください。
* まずは 地形、川、水辺、橋、樹木、看板、プレイヤーの3D表現 と、キーボード（または画面タップ）での移動 を実装してください。
* 可能ならマウスドラッグ（スマホならスワイプ）で軽い視点操作も追加してください。ただし最優先は安定動作です。

目指す見た目（グラフィックの高度化）

* 最新のインディー3Dゲームや次世代JRPGのような、美麗で幻想的なビジュアル
* 物理ベースマテリアル（MeshStandardMaterial）の徹底活用:
  - 草地や崖、木、看板などは、単色ベタ塗りではなく、光沢感（roughness）や金属感（metalness）を微調整してリアルな質感を表現してください。
  - 川や水辺は、透明度や滑らかな光の反射を持たせ、生き生きとした「美しい水の表現」にしてください。
* リッチなライティングと影の表現:
  - 環境光（AmbientLight）に加え、ドラマチックな光と影を落とす方向性光源（DirectionalLight、シャドウマップ有効）を設定し、地面や橋に美しい影をリアルタイムに描写してください。
  - ポイントライト（点光源）なども活用し、エリア全体に幻想的な陰影と空気感（フォグ効果など）を持たせてください。
* 青髪の主人公（プレイヤー）は、メタリックな輝きや発光、あるいは美しいグラデーションを持つ魅力的な3Dオブジェクト（簡易形状の組み合わせで可）として配置してください。

UI方針

* iPhone縦持ちを強く意識してください（縦長画面に美しく収まるカメラアングル）。
* マップが主役です。画面全体にダイナミックに3D空間が広がるようにしてください。
* 画面下に無駄な専用操作エリアを大きく取らないでください。
* 必要なら仮のHUD（キャラクター名やHPなど）を、CSSでゲーム画面上に美しくオーバーレイ表示してください。

## 7. 品質基準と比較方法

3D化、PBR使用、ライトの数、コード量、テスト成功を品質合格の代用にしない。次を1項目ずつ「未達／同等／上回る／評価不能」で比較し、画面の具体箇所と修正案を付ける。

| 軸 | 同等以上の判断条件 |
|---|---|
| 構図 | 橋・川・森・人物が主従を持ち、縦画面で世界が主役 |
| 地形 | 草地・崖・岸に厚みと素材の変化があり、単純平面に見えない |
| 植生 | 樹冠・枝葉・幹・下草が重なり、単純な円錐の反復で終わらない |
| 橋 | 木材の構造・木目・接合・接地が読み取れる |
| 水 | 青い板で終わらず、深さ・岸・光・動きが統一される |
| 人物 | 青髪の主人公として判別でき、背景と造形密度・接地が合う |
| 光と色 | 統一した光方向、陰影、色調。白飛び・過剰発光で情報を失わない |
| 全体の密度 | 必要な細部があり、余白も意図される。物量だけで埋めない |
| UI | 控えめで読みやすく、画面を大きく消費しない |

最低条件：主要な視覚軸に未達を残さず、実ゲーム画像で比較する。「以上」のうち同等か上回るかを明記する。内部評価は暫定であり、Ownerの主観的合格を捏造しない。参考画像と別の美術方向へ大きく変える場合は選択肢を提示する。

動画評価：橋を渡る、木の前後を通る、岸際で止まる、方向転換、待機、水の動き、必要なら限定視点変更。静止画だけ綺麗でも完成にしない。

高画質／iPhone実用のそれぞれで、解像度・端末・設定・SHAを画像と対応させる。PCの高画質画像をiPhoneの証拠として使わない。

## 8. 性能・操作基準

以下は実装開始用の提案目標であり実測結果ではない。対象端末と実測に応じて調整する場合、理由と画質差を記録し、合格基準を黙って緩めない。

- iPhone縦持ち：60fpsを目標、30fpsを実用下限の初期基準とする。ウォームアップ後の固定経路でフレーム時間の中央値とp95、長い停止を測る。p95は33.3ms以下を初期目標とする。
- 初期ロード：環境・通信条件・転送量と操作可能までの秒数を報告。無条件の秒数保証はしない。
- 5分程度の連続移動、水・影の動作、バックグラウンド復帰を確認。再読込・黒画面・入力残留・顕著な時間経過による悪化を記録する。
- draw calls、三角形数、テクスチャ量、描画解像度、影設定を記録。端末で取得できない値は推定と区別する。
- 解像度、影、植生密度、水の反射、後処理を設定として調整できるようにする。最適化はM10だけでなく、M02以降で軽く測定する。
- pointerup/cancel、blur、visibilitychangeで移動を解除する。画面タップは誤作動しない移動方式を一つ選び、表示する。画面外の大きな操作パネルを作らない。
- キーボードの斜め移動速度、フレームレート依存、衝突、橋への乗降、落下防止を確認する。
- カメラ操作は任意。導入する場合、角度を制限し、移動ジェスチャーと分離する。常時自由視点を品質達成の条件にしない。
- 描画機能や素材の読込失敗時は、理由が分かる表示を出す。黒画面のまま放置しない。

## 9. M00〜M12 実行工程

各工程に制作、検証、比較修正、再開記録を含む。1工程は複数セッションにまたがってよい。合格前に後工程を完了扱いにしない。M05の静止画合格は暫定美術ゲートであり、最終完成ではない。

### M00 独立プロトタイプの準備
入力：本書、参照2画像、Gold/mainの最新状態。
作業：SHA固定、適用ルール、既存未コミット作業、CI・公開トリガーを確認。隔離した作業場所を作る。参照画像とREADME、進行記録を置く。既存ゲームの全履歴を無目的に読まない。
成果物：作業場所・開始SHA・起動方針・画像。
合格：本線を上書きせず、参照画像へアクセスできる。

### M01 画作りと比較契約
作業：目標画像から視点、構図、色、素材密度、人物比率、光方向を定義する。3Dでも目標の魅力が残る美術方針を記述。初期方針は幻想的で絵画的なJRPG風とし、写実性だけを追わない。主比較カメラと歩行経路を固定する。
成果物：アート仕様、カメラ候補、品質評価表。
合格：第7節の各軸に具体的な到達像がある。

### M02 Three.js実行基盤
作業：実装時の公式資料でバージョン・CDN・モジュール読込を確認して固定。Canvas/WebGL描画、縦画面リサイズ、ロード表示、エラー表示、タッチ・キーボード、描画ループを実装。独立した状態を使う。
成果物：起動可能な検証ページと起動コマンド。
合格：対象ブラウザで表示・移動し、入力解除と再表示が動く。機能合格のみで美術合格とはしない。

### M03 仮形状で構図と通行を検証
作業：地面、崖、川、橋、木、人物を配置。通行面・衝突・カメラをそろえ、橋から川に歩いて落ちないようにする。周縁が見切れた際の穴を確認。
成果物：仮形状の画面と短い歩行記録。
合格：1画面相当の構図が成立し、橋・岸の移動が破綻しない。仮形状はここでは可。

### M04 本制作アセット
作業：第6節のモデルと素材を制作・調達する。主要素材を同じ照明下で並べて密度・縮尺・色を合わせる。人物はリグまたは適切なアニメーション方式を用意。コードで生成するモデルも最終品質を満たせば可。
成果物：素材、出所記録、manifest、検査用表示。
合格：単純図形と単色だけの主要素材を最終素材としない。素材不足なら不足名・実行可能な代案を記録する。

### M05 代表画面の美術品質ゲート
作業：橋・川・草・崖・木・人物が一緒に見える構図へ本素材を入れ、基本照明と水を設定する。実際のWebGL描画を目標画像と並べて批評する。
成果物：実ゲーム画像、設定・SHA、比較表、上位3つの不足。
合格：地形・植生・橋・人物・構図が目標に比べ著しく弱くなく、全体の方向が成立。未達ならM01/M03/M04へ戻る。単なる3D化を理由に進まない。水・照明・動作の最終合格は後工程で取る。

### M06 地形・植生・橋の完成
作業：草地、崖面、岸、枝葉、木の変種、下草、橋の接合・支柱・木目を完成。全域への単純なコピーを避け、主要視線と通路を保つ。
成果物：代表構図と周辺位置の画面。
合格：継ぎ目、浮き、目立つ繰返し、単純形状の仮素材が主要部分に残らない。

### M07 水・照明・空気感
作業：水の深浅・波・反射・岸際を仕上げる。反射は方式を明記し、高画質・実用設定の差を示す。方向性光、環境光、実際の影、必要な霧・点光源・後処理を統一する。マテリアル・テクスチャの色空間と色調整を確認。
成果物：静止画、水と影の動作動画、性能差。
合格：青い板や過剰な発光で代用せず、画面の細部を保った美しい水・光になる。

### M08 人物・移動・カメラ
作業：青髪の主人公の待機・歩行・方向転換・接地を完成。橋上の高さ、衝突、移動速度、カメラ追従を整える。任意の視点操作は安定動作を確認して追加する。
成果物：移動記録と入力検証。
合格：背景に合う人物が自然に歩き、足滑り・地面貫通・操作残留がない。

### M09 全エリアとUI
作業：1画面相当の対象と必要な周縁に品質を展開。看板、草花、岩を配置。CSSの控えめな仮HUDを重ね、safe-areaと画面内の操作を整える。仮HPはデモ値として区別し、未実装戦闘があるように装わない。
成果物：複数位置・画面比率の画像。
合格：一つの撮影位置以外も破綻せず、マップが主役で、HUDは読めて邪魔にならない。
